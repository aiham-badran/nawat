| :----------------- | :--------------------------------------------------- |

| **نوع المنتج**     | مكتبة / نواة محرر (Low-level Core) تعمل على المتصفح  |

## 1. الملخص التنفيذي

`Nawat` هو **نواة محرر نصوص كتلي عربي** يعمل بالكامل في المتصفح، ويُوزَّع كمستودع GitHub يمكن استنساخه أو ربطه كمصدر (dependency) في أي تطبيق ويب عربي. لا يهدف هذا المنتج إلى أن يكون تطبيق ملاحظات أو محررًا نهائيًا بواجهة مستخدم كاملة، بل إلى أن يكون **الطبقة الأساسية** التي تُبنى فوقها تطبيقات مختلفة: ملاحظات، محادثات، صياغة عقود، أو أي منتج يحتاج تحريرًا نصيًا عربيًا منظمًا بالكتل.

قيمته الأساسية ثلاثية: (1) **دعم RTL أصلي** لا يحتاج المستهلك إلى معالجته، (2) **مخرجات JSON منظّمة** بدل HTML غير المهيكل، مما يسهّل التخزين والمزامنة والتحويل إلى تطبيقات أخرى، (3) **قابلية توسّع عبر نظام كتل (Block Registry)** يسمح لكل تطبيق مستهلك بإضافة أنواع كتل خاصة به دون المساس بالنواة.

**فلسفة MVP**: نواة صغيرة، واضحة، قابلة للاختبار، تُوزَّع عبر GitHub، مع **API برمجي فقط** (بدون مكونات واجهة جاهزة). الواجهة الجاهزة والترجمة الإنجليزية والنشر على NPM مؤجلة إلى الإصدار التالي.

## 2. المشكلة والسياق

### 2.1 المشكلة

بناء محرر نصوص عربي كتلي من الصفر يتطلب حل مشكلات BiDi (ثنائية الاتجاه) ومعالجة `contenteditable` وإدارة التحديد والمؤشر (Caret) عبر المتصفحات. هذه مشكلات مكلفة زمنيًا ومكررة عبر كل فريق يريد بناء تطبيق عربي يحتاج تحريرًا نصيًا. لا توجد اليوم نواة عربية خفيفة ومفتوحة يمكن “تضمينها” في تطبيق ويب جديد دون إعادة بناء هذه الطبقة في كل مرة.

### 2.2 السياق

`Blok` يوفر محركًا كتليًا ناضجًا: **Headless** (لا يفرض واجهة)، **JSON in/JSON out** (لا تحليل HTML)، **69 لغة مع RTL مدمج**، و**21 فضاء API** للكتل والمؤشر والتحديد. هذا يجعله أساسًا مناسبًا لنواة عربية، لكنه **ليس منتجًا عربيًا** بحد ذاته: لا يأتي بمدير حالة، ولا بواجهة عربية، ولا بنظام تسجيل كتل موحد للمستهلكين. هذه الفجوة هي بالضبط ما تملؤه `Nawat`.

## 4. النطاق

### 4.1 داخل النطاق (MVP — الإصدار الأول)

- نواة محرر كتلي عربي تعمل في المتصفح، مبنية على `Blok`.
- حاوية عربية `dir="rtl"` مع دعم تقني للإنجليزية (LTR) داخل المحتوى، مع **واجهة تحكم عربية فقط**.
- أنواع كتل أساسية: **فقرة، عنوان (H1–H3)، قائمة نقطية، قائمة مرقمة، اقتباس**.
- أدوات سطرية أساسية: **عريض، مائل، رابط**.
- **نظام تسجيل كتل (Block Registry)** يسمح للمستهلك بتسجيل كتلة جديدة عبر `registerBlock(definition)`.
- إدارة حالة عبر **Zustand**: المستند (خريطة كتل مسطحة)، الكتلة النشطة، اللغة، الاتجاه.
- حفظ واسترجاع عبر **JSON** فقط (`save()` / `render(data)`).
- **API برمجي فقط** (Low-level): `createEditor`, `registerBlock`, `save`, `render`, `getDocument`, `setReadOnly`. لا مكونات React/Vue جاهزة.
- **التوزيع عبر GitHub**: README عربي + دليل API + مثال تضمين HTML/JS قابل للتشغيل + ملف `TESTING.md`.
- **اختبارات وحدات** لمنطق النواة + اختبار تكامل خفيف (Vitest + happy-dom) + قائمة فحص يدوي لحالات RTL.

### 4.2 خارج النطاق (صريحًا)

| البند                                              | الحالة                    |
| :------------------------------------------------- | :------------------------ |

## 7. البنية التقنية المقترحة (Technical Architecture)

### 7.1 المكونات

```
┌─────────────────────────────────────────────────────┐
│                   التطبيق المستهلك                      │
│  (Notes / Chat / Contracts / ...)                    │
└─────────────────────┬───────────────────────────────┘
                      │  يستدعي Nawat API (برمجي فقط)
┌─────────────────────▼───────────────────────────────┐
│                    Nawat Core                        │
│  ┌──────────────┐  ┌──────────────┐  ┌───────────┐  │
│  │ Block Registry│  │ Zustand Store│  │ RTL Layer │  │
│  │ (كتل أساسية + │  │ (DocumentModel│  │ (dir, i18n)│  │
│  │  كتل مخصصة)   │  │  + Active)   │  │           │  │
│  └──────┬───────┘  └──────┬───────┘  └─────┬─────┘  │
│         │                 │                 │        │
│         └─────────────────┼─────────────────┘        │
│                           ▼                          │
│                  ┌─────────────────┐                 │
│                  │  Blok Adapter   │                 │
│                  │ (عزل API Blok)  │                 │
│                  └────────┬────────┘                 │
│                           ▼                          │
│                  ┌─────────────────┐                 │
│                  │   Blok Engine   │                 │
│                  │ (JSON in/out,   │                 │
│                  │  RTL مدمج، APIs) │                 │
│                  └─────────────────┘                 │
└─────────────────────────────────────────────────────┘
```

**قرار معماري مهم**: يُعزل `Blok` خلف طبقة تكييف (`Blok Adapter`) ولا يُكشف API الخاص به مباشرة للمستهلك. هذا يحمي `Nawat` من تغييرات مستقبلية في `Blok`، ويمنحنا حرية استبدال المحرك لاحقًا إن لزم.

### 7.2 نماذج البيانات الأساسية

```typescript
// نموذج الكتلة (يتوافق مع مخرجات Blok)
interface Block {
  id: string;
  type: "paragraph" | "heading" | "list" | "quote" | string; // string للكتل المخصصة
  data: Record<string, unknown>; // بيانات خاصة بنوع الكتلة (JSON)
}

// نموذج المستند في Zustand
interface DocumentModel {
  rootBlockIds: string[];
  blocks: Record<string, Block>;
}

// تعريف الكتلة القابل للتسجيل
interface BlockDefinition {
  type: string;
  label: { ar: string; en?: string }; // en اختياري في MVP
  defaultData: () => Record<string, unknown>;
  render: (block: Block, api: BlockApi) => HTMLElement;
}

// واجهة النواة العامة (Low-level API)
interface NawatEditor {
  save(): DocumentModel;
  render(data: DocumentModel): void;
  getDocument(): DocumentModel;
  setReadOnly(value: boolean): void;
  destroy(): void;
}

function createEditor(options: {
  container: HTMLElement;
  locale: "ar" | "en";
  data?: DocumentModel;
  slashMenu?: boolean;
  onChange?: (doc: DocumentModel) => void;
  onSave?: (doc: DocumentModel) => void;
  onReady?: () => void;
}): NawatEditor;
```

### 7.3 قرارات معمارية حاسمة

| القرار         | الاختيار                          | السبب                                                    |
| :------------- | :-------------------------------- | :------------------------------------------------------- |
| المحرك         | `Blok` (خلف Adapter)              | دعم RTL مدمج، JSON out، Headless، 21 API namespace       |
| إدارة الحالة   | `Zustand`                         | خفيف، بلا boilerplate، يسمح بمتجر لكل محرر (نمط factory) |
| نموذج البيانات | خريطة مسطحة (`Record<id, Block>`) | تحديث O(1)، سهولة النقل، توافق مع CRDT لاحقًا            |
| التخزين        | JSON فقط                          | لا HTML؛ يسهّل التخزين والمزامنة والتحويل                |
| RTL            | يعتمد على `Blok` + طبقة `dir`     | لا نعيد اختراع BiDi؛ نضيف الضبط العربي فوق المحرك        |
| واجهة المستهلك | API برمجي فقط                     | يقلل النطاق ويؤجل مكونات React للإصدار التالي            |
| التوزيع        | GitHub فقط                        | يلغي إعداد النشر وsemver في MVP                          |

## 8. معايير القبول (Acceptance Criteria)

- **AC-01**: عند تضمين `Nawat` في صفحة عربية، تظهر الكتل باتجاه RTL تلقائيًا دون أي CSS إضافي من المستهلك.
- **AC-02**: يمكن للمستهلك تسجيل كتلة مخصصة (مثل “بند عقد”) عبر `registerBlock`، وتظهر في المحرر وتُحفظ ضمن JSON بنوعها الخاص.
- **AC-03**: استدعاء `save()` يُرجع JSON صالحًا يحتوي `blocks` كخريطة و`rootBlockIds` كقائمة، واستدعاء `render(savedJSON)` يعيد بناء نفس المحتوى.
- **AC-04**: تبديل اللغة من العربية إلى الإنجليزية يغيّر اتجاه الحاوية إلى LTR دون فقدان المحتوى.
- **AC-05**: إضافة كتلة جديدة أو حذفها أو نقلها برمجيًا تنعكس فورًا في حالة Zustand وفي واجهة المحرر.
- **AC-06**: المستند الذي يحتوي 100 كتلة نصية يظل قابلاً للكتابة دون تأخر ملحوظ (أقل من 50ms للحفظ، أقل من 16ms لتحديث الكتلة).
- **AC-07**: يمكن تشغيل مثال `examples/basic-html/` من المستودع دون أي تعديل باستثناء فتح الملف في خادم محلي بسيط.
- **AC-08**: ملف `TESTING.md` موجود ويحدد بوضوح: (أ) ما تغطيه اختبارات الوحدات، (ب) ما يغطيه اختبار التكامل، (ج) قائمة فحص يدوي لحالات RTL الحرجة.

## 13. استراتيجية الاختبار (Testing Strategy)

### 13.1 الفلسفة

جوهر محرر النصوص يكمن في سلوك DOM وRTL والمؤشر، وهي أمور **لا تلتقطها اختبارات الوحدات التقليدية**. لذلك تتبنى `Nawat` استراتيجية ثلاثية الطبقات توازن بين الحماية الآلية والتكلفة:

1. **اختبارات وحدات** للمنطق (آلية، إلزامية، تكلفة منخفضة).
2. **اختبار تكامل خفيف** للتهيئة (شبه آلية، تكلفة منخفضة).
3. **قائمة فحص يدوي** لحالات RTL الحرجة (يدوية، موثقة).

### 13.2 الطبقة 1: اختبارات الوحدات (Vitest)

| المنطقة                | ما يُختبر                                                           | الأداة |
| :--------------------- | :------------------------------------------------------------------ | :----- |
| **متجر Zustand**       | إضافة/حذف/نقل كتلة، تبديل اللغة، تبديل الاتجاه، تحديث الكتلة النشطة | Vitest |
| **Block Registry**     | تسجيل كتلة، منع التكرار، استرجاع تعريف، السلوك عند نوع غير مسجل     | Vitest |
| **JSON Round-trip**    | `save()` ثم `render()` يعيد نفس البنية (بدون DOM)                   | Vitest |
| **منطق الاتجاه**       | دالة نقية `resolveDirection(locale, content)` تحدد `dir`            | Vitest |
| **التحقق من المدخلات** | رفض تعريف كتلة ناقص الحقول الإلزامية                                | Vitest |

**هدف التغطية**: ≥ 70% لمنطق النواة.

### 13.3 الطبقة 2: اختبار التكامل الخفيف (Vitest + happy-dom)

| السيناريو               | ما يتحقق منه                                                   |
| :---------------------- | :------------------------------------------------------------- |
| **تهيئة المحرر**        | `createEditor` تُنشئ DOM صالحًا داخل الحاوية وتستدعي `onReady` |
| **حفظ بعد إدخال برمجي** | إدخال كتلة برمجيًا ثم `save()` يُرجع JSON بالبنية المتوقعة     |
| **استرجاع**             | `render(savedJSON)` يعيد بناء نفس عدد الكتل وأنواعها           |
| **القراءة فقط**         | `setReadOnly(true)` يمنع التعديل برمجيًا                       |

**ملاحظة**: `happy-dom` أخف من `jsdom`، لكنه **لا يطابق المتصفح الحقيقي** في `contenteditable` و`Selection`. لذلك لا نعتمد عليه لاختبار سلوك المؤشر.

### 13.4 الطبقة 3: قائمة الفحص اليدوي (`TESTING.md`)

حالات يجب فحصها يدويًا في متصفح حقيقي قبل كل إصدار:

- [ ] كتابة فقرة عربية خالصة — الاتجاه RTL صحيح.
- [ ] كتابة فقرة تبدأ برقم لاتيني ثم نص عربي — الاتجاه RTL صحيح.
- [ ] كتابة فقرة مختلطة (عربي + إنجليزي) — المؤشر يتحرك بشكل طبيعي عبر الحدود.
- [ ] كتلة اقتباس تبدأ بحرف لاتيني — شريط الاقتباس في الجهة الصحيحة (يمين).
- [ ] قائمة مرقمة عربية — الأرقام على اليمين، النص على اليسار.
- [ ] التنقل بلوحة المفاتيح (Tab / Shift+Tab / الأسهم) بين الكتل.
- [ ] تبديل اللغة من `ar` إلى `en` — الاتجاه يتحول دون فقدان المحتوى.
- [ ] `setReadOnly(true)` — لا يمكن التعديل بالنقر أو لوحة المفاتيح.
- [ ] قائمة `/` (إن فُعّلت) — تظهر بأسماء عربية وتُدرج الكتلة الصحيحة.

### 13.5 ما هو مؤجل صريحًا

- **اختبارات متصفح آلية (Playwright/Cypress)**: مؤجلة إلى ما بعد MVP، عندما تصبح واجهة المستخدم (النسخة القادمة) موجودة ويصبح اختبار السيناريوهات الكاملة مجديًا.
- **اختبارات الأداء الآلية**: مؤجلة؛ تُقاس يدويًا في MVP مقابل NFR-01.

## 14. كيفية التضمين من GitHub (Distribution)

بما أن MVP لا يُنشر على NPM، يوفر README ثلاث طرق للتضمين:

### 14.1 الطريقة 1: استنساخ مباشر (للتجربة والتطوير)

```bash
git clone https://github.com/<org>/nawat.git
cd nawat
npm install
npm run build
# ثم افتح examples/basic-html/index.html عبر خادم محلي
npx serve examples/basic-html
```

### 14.2 الطريقة 2: ربط كمصدر في `package.json` (للتطبيقات المستهلكة)

```json
{
  "dependencies": {
    "nawat": "github:<org>/nawat#v0.1.0"
  }
}
```

أو عبر مسار محلي أثناء التطوير المتزامن:

```json
{
  "dependencies": {
    "nawat": "file:../nawat"
  }
}
```

### 14.3 الطريقة 3: Git Submodule (للمشاريع التي تريد تثبيت إصدار)

```bash
git submodule add https://github.com/<org>/nawat.git vendor/nawat
```

### 14.4 مثال التضمين الأدنى (HTML/JS)

```html
<!DOCTYPE html>
<html lang="ar" dir="rtl">
  <head>
    <meta charset="UTF-8" />
    <title>مثال تضمين Nawat</title>
  </head>
  <body>
    <div id="editor"></div>
    <script type="module">
      import { createEditor, registerBlock } from "./nawat/dist/index.js";

      // تسجيل كتلة مخصصة (اختياري)
      registerBlock({
        type: "contract-clause",
        label: { ar: "بند عقد" },
        defaultData: () => ({ text: "" }),
        render: (block, api) => {
          const el = document.createElement("div");
          el.className = "contract-clause";
          el.textContent = block.data.text || "بند جديد...";
          return el;
        },
      });

      const editor = createEditor({
        container: document.getElementById("editor"),
        locale: "ar",
        onChange: (doc) => console.log("تغيّر المستند", doc),
        onReady: () => console.log("المحرر جاهز"),
      });

      // حفظ عند الحاجة
      document.addEventListener("keydown", (e) => {
        if (e.ctrlKey && e.key === "s") {
          e.preventDefault();
          const json = editor.save();
          localStorage.setItem("nawat-doc", JSON.stringify(json));
        }
      });
    </script>
  </body>
</html>
```
