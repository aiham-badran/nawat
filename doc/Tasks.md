# تفكيك المتطلبات الوظيفية (FR-01 → FR-15) إلى مهام هندسية

## Nawat — MVP v0.1

> **ملاحظة**: المهام مرتبة حسب **التبعية (Dependency Order)**، لا حسب رقم المتطلب. كل مهمة تشير إلى المتطلب (FR) الذي تخدمه، ومهامها السابقة، ومعيار إنجازها. لا تقديرات زمنية — القرار يعود للفريق.

---

## 🗺️ خريطة التبعيات الكلية

```
المرحلة 0: التأسيس
     │
     ▼
المرحلة 1: طبقة البيانات (Types + Store + Registry + Direction)
     │
     ▼
المرحلة 2: Blok Adapter (عزل المحرك + CRUD برمجي)
     │
     ▼
المرحلة 3: API العام (createEditor, save, render, setReadOnly, getDocument, callbacks)
     │
     ├──────────────┬──────────────┐
     ▼              ▼              ▼
المرحلة 4:        المرحلة 5:     المرحلة 6:
الكتل الأساسية   الأدوات السطرية   RTL/LTR
     │              │              │
     └──────────────┼──────────────┘
                    ▼
             المرحلة 7: الميزات الاختيارية (Slash Menu, Labels)
                    │
                    ▼
             المرحلة 8: الأمثلة والتوثيق
                    │
                    ▼
             المرحلة 9: التحقق النهائي
```

## 🔀 ملاحظات على الترتيب

1. **المرحلة 1 قبل 2 قبل 3**: لا يمكن بناء API عام قبل وجود Store وRegistry وAdapter.
2. **المرحلة 4 و5 و6 متوازية نظريًا** بعد المرحلة 3، لكن عمليًا يُنصح بإكمال 4 (الكتل) أولًا لأن 5 (الأدوات السطرية) تعتمد على وجود كتلة نصية، و6 (RTL) يعتمد على وجود كتل لعرضها.
3. **T-05-05 (لوحة المفاتيح) وT-09-05 (الوصولية)** يمكن دمجهما في مهمة واحدة إذا أراد الفريق تقليل التجزئة، لكن فصلهما يوضح أن التنقل جزئية من NFR-04 لا من FR-03.
4. **T-07-01 (Slash Menu)** هو المهمة الوحيدة التي تتطلب بناء واجهة DOM صغيرة داخل النواة — يمكن تأجيله إلى ما بعد MVP إذا ضاق الوقت، لأنه “ينبغي” لا “يجب”.
